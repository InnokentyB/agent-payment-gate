# Local OpenZeppelin integration — 24 October 2026

Goal: a human delegates restricted token transfers to an agent, and Stellar enforces those restrictions independently of our Node process. Approved surface: existing CLI prototype plus offline contract harness. No public service, mainnet, provider call or testnet transaction is activated by this change.

Evidence baseline: OpenZeppelin stellar-contracts tag v0.7.1, commit 3f81125bed3114cc93f5fca6d13240082050269a; source inspected 24 October. Exact stellar-accounts 0.7.1 / soroban-sdk 25.3.0; Cargo.lock captures transitives. Important divergence: this release signs sha256(host payload || XDR rule IDs), not the AuthDigestPreimage in newer docs. Upstream examples are MIT; retain notices. HackMeridian build/FAQ checked 24 October. Prework eligibility remains unresolved, disclose baseline and event delta.

Account owner rule0 alone manages rules. Agent rule1 targets one token contract, expires at a ledger and combines Ed25519 signer, OZ rolling SpendingLimit and our RecipientPolicy. Recipient policy checks exact token/transfer/from/account/recipient and positive per-payment cap. No general agent Default rule; no agent policy-management authority. Owner deliberately retains full control of their own wallet.

Scenarios: S1 allowed transfer changes actual token balances; S2 wrong recipient rejected with no balance or budget change; S3 per-payment cap rejected; S4 cumulative window cap rejected; S5 rule expiry rejected; S6 owner removes agent rule, subsequent transfer rejected; S7 agent cannot remove policy/change limits; S8 invalid/tampered signatures and rule substitution rejected; S9 window rollover restores allowance. Rust harness signs host authorization entries and executes transfers in Soroban test Env; JS tests check pinned signature payload and fail-closed identity assertion. These are local acceptance checks, not deployed-network e2e or proof of provider availability.

Didit boundary: server creates verification session, retrieves authoritative decision, binds it to authenticated owner and only after explicit consent signs rule creation. Persist minimal provider/session/status/expiry linkage. Never accept browser Approved, never put documents/biometrics on-chain. Local helper is NOT a completed provider adapter or identity revocation oracle. Live identity expiry/revocation sync is out of this local slice; agent rule expiry bounds authorization lifetime.

Risk: synthetic assets/keys only, no customer reliance. Live testnet/deployed-WASM smoke and owner UAT remain required before claiming a working network demo. Wallet seeds are runtime files outside Git, owner-only permissions, no seed logging. Identity readiness does not imply delegation and authorization does not prove settlement.
